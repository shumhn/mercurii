# Mercury backend and program completion plan

The next build phase excludes new Agent behavior. Each milestone must be repeatable for a newly configured Circle devnet USDC company, not just for the existing proof wallets.

1. **Company onboarding.** The policy, private snapshot, capped Finance grant, company funding, and recipient readiness now have stepwise backend endpoints. Signed transaction receipts are bound to prepared messages in a local journal. A fresh Circle devnet USDC company completed policy, snapshot, and Finance grant setup; private receive and recipient onboarding were verified through the HTTP endpoints. Wallet login/signing, safe recovery for abandoned receipt IDs, and multi-company server configuration remain.
2. **Team access and revocation.** Root Finance revocation now has a PER account scan and a receipt-backed Founder-signed cleanup planner for requests and snapshot. A fresh devnet company showed that grant revocation alone left historical reads open, while cleanup denied Finance's TEE token and kept Founder access. The planner reports Finance-requested records and AgentPolicy ACLs as residuals; those, Manager-specific cleanup, discoverable member/grant records, persistent Requester/Viewer access, branch scope, and role rotation remain. Recheck read denial with the revoked key for each completed cleanup.
3. **Guided payment and tracking.** A local, mode-0600 flow journal derives one private request from each opaque payment ID and stores only public request identity plus a hash of private terms. It builds shell, delegation, ER permission, privacy activation, private submission, and approval in order, with receipt confirmation before every next state transition; approved flows create the existing execution journal. A Founder-driven Circle devnet USDC flow completed its whole request-to-payout-to-snapshot path, refused a replay, and the complete path was repeated on a newly configured Circle devnet company. Finance and Manager approve using their existing grants. Remaining: durable multi-company storage, background reconciliation and alerting, abandoned-preparation recovery, recipient-balance evidence when available, and automatic refresh after receive/payout.
4. **Human-approved payroll.** Maintain a private employee roster; create a run with item IDs, total and period budget, one human approval, one-time item payouts, and per-item success/failure/retry state. Keep salary data scoped to Founder/Finance and each recipient. Prove partial failure recovery on devnet.

The first three milestones plus a working payroll run are the backend/program MVP. Frontend wallet login and signing are separate integration work. Mainnet requires additional security and recovery work described in [ARCHITECTURE.md](ARCHITECTURE.md).
